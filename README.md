# YosoiX

X（旧Twitter）デスクトップWeb画面向けの統合カスタマイズ Microsoft Edge 拡張機能（Manifest V3）です。

## 主な機能
1. **左サイドバーの項目別非表示**: 不要なナビゲーション項目・「もっと見る」項目・「ポストする」ボタンを選択して非表示（投稿ボタンは初期状態では非表示）
2. **右サイドバー全体の非表示**: トレンド等のサイドバーを非表示にし、中央タイムラインを拡張
3. **引用リポスト一覧ボタン**: タイムライン上の各ツイートから詳細画面を開かずに直接引用一覧へアクセス
4. **リポスト（リツイート）一覧ボタン**: 引用ボタンの右隣に配置し、タイムラインから直接リポスト一覧へアクセス
5. **プロフィールの初期表示を「すべて (/all)」に**: ユーザー名やアイコンをクリックしてプロフィールを開いた際、リポストを含む全投稿が表示される `/all` ページを自動初期表示
6. **メディア一括ダウンロード**: 原寸画像や最高画質MP4（動画・GIF）を投稿単位でワンクリック保存
7. **設定画面 (Options UI)**: 日本語・ライト/ダークモード対応、保存時即時反映

## 開発環境とビルド

### 省リソース動作

- X / Twitter 以外のページにはスクリプトを注入しません。常時ポーリングやService Workerの常駐維持は行いません。
- Xタブが非表示の場合はDOM監視・操作イベント・JSON解析・画面更新を休止し、再表示時に現在のDOMを同期します。
- 非表示中も、X自身が受信した対象APIレスポンスだけを直近4件・合計約4MiBの文字列サイズ上限で一時保持します。再表示時は1フレームにつき1件ずつ解析します。追加のAPIリクエストは送りません。
- マスターOFF、または引用・リポスト・保存ボタンがすべてOFFの場合は、対象APIの読み取り・解析・一時保持も停止します。監視対象と操作イベントは有効な機能に限定します。
- API受信時は投稿IDに対応するDOMだけを更新し、重複通知はフレーム単位でまとめます。削除されたDOMへの参照は解放し、大量の投稿追加は25件ずつ処理します。
- レスポンス読み取りは1件4MiB・同時2件まで、投稿メタデータは500件・30分までに制限します。上限を超えたデータやOFF中に受信したデータは保持しないため、必要なメディア情報がない場合はページ再読み込みが必要です。
- ダウンロードがOFFの場合はメディア抽出を省略し、直近の上限内レスポンスから再有効化時にメディア情報を復元します。配布用ビルドは圧縮します。

### 必要要件
- Node.js v20 以上
- **pnpm**（本プロジェクトは pnpm 必須です）

### コマンド
```powershell
# 依存パッケージインストール
pnpm install

# 型チェック
pnpm run typecheck

# ユニットテスト実行
pnpm test

# 展開用データのビルド (dist/ に出力、固定ID鍵を自動適用)
pnpm run build

# パッケージ化 (署名済み CRX + 展開用 ZIP + ストア提出用 ZIP を release/ に生成)
pnpm run package
```

## 拡張機能のパッケージ化と 32 桁 ID の固定化について

### 32 桁 ID が変わらない仕組み
Chromium（Edge / Chrome）では、通常「展開して読み込み」を行うとフォルダーの絶対パスから仮の 32 桁 ID が計算されます。そのためフォルダー移動やマシン変更、再パッケージ化を行うたびに ID が変わり、**`chrome.storage.local` の設定データ消失や権限リセット** が発生します。

YosoiX ではこの問題を解決するため、以下の工夫を施しています：

1. **秘密鍵 (`key.pem`) の自動生成・永続化**:
   - 初回ビルドまたはパッケージ化時に、RSA 2048bit の秘密鍵 `key.pem` をプロジェクト直下に自動生成します（すでに存在する場合は既存の鍵を再利用します）。
   - この秘密鍵は Git 管理から除外（`.gitignore` 済み）されます。
2. **公開鍵 (`manifest.json` の `key`) による ID 固定**:
   - 秘密鍵から取り出した公開鍵（SPKI DER Base64）を `manifest.json` の `"key"` プロパティに自動反映します。
   - Chromium は `"key"` が指定されている拡張機能に対して、**フォルダーの場所に関係なく常に同一の 32 桁 ID を割り当てます**。
   - これにより、コード修正や機能強化、`pnpm run build` を何度実行しても、同じ ID で継続動作し、設定値が引き継がれます。
3. **署名済み CRX パッケージの同一 ID 保証**:
   - `pnpm run package` では、同じ `key.pem` を用いて Edge / Chrome CLI による公式署名（CRX3 形式）を行います。
   - そのため、開発中の「展開して読み込み」版と、パッケージ化された `.crx` 版で **完全に同じ 32 桁 ID** が維持されます。

> [!IMPORTANT]
> プロジェクト直下に生成される `key.pem` を削除すると、拡張機能 ID が変わってしまいます。チーム外に漏洩しないよう安全に保管・バックアップしてください。

### パッケージ成果物 (`release/`)
リポジトリ直下の `package.bat` をダブルクリックするか、ターミナルで `pnpm run package` を実行すると、`release/` ディレクトリに以下の成果物が生成されます（完了時に出力先フォルダーがエクスプローラーで自動表示されます）：

- **`yosoix-vX.X.X.crx`**: Edge / Chrome 公式の署名済み拡張機能パッケージ。拡張機能管理画面（`edge://extensions`）にドラッグ＆ドロップして即座にインストール可能。
- **`yosoix-vX.X.X-unpacked.zip`**: 解凍して「展開して読み込み」できる配布用 ZIP。固定 ID 用の `"key"` が含まれているため、別 PC で解凍しても同じ ID で動作します。
- **`yosoix-vX.X.X-store.zip`**: Microsoft Edge Add-ons または Chrome Web Store の開発者ダッシュボードへ提出するための標準 ZIP。

## Microsoft Edge へのインストール手順

### 方法A: ワンクリックバッチを使用する場合 (推奨)
1. リポジトリ直下の `install.bat` をダブルクリックして実行します。
2. 自動でビルドが実行され、展開先フォルダー（`dist`）がエクスプローラーで自動的に開きます（パスも自動でクリップボードにコピーされます）。
3. Microsoft Edge を開き、アドレスバーに `edge://extensions` を入力します。
4. 画面左下の **「開発者モード」** を ON にします。
5. **「展開して読み込み」** をクリックし、開いた `dist` フォルダーを選択すればインストール完了です。

### 方法B: 署名済み CRX パッケージを直接インストールする場合
1. リポジトリ直下の `package.bat` をダブルクリック（または `pnpm run package`）してパッケージを生成します。
2. `edge://extensions` を開き、「開発者モード」を ON にします。
3. 生成された `release\yosoix-vX.X.X.crx` を Edge の拡張機能画面にドラッグ＆ドロップしてインストールします。

### 方法C: コマンドラインから展開フォルダーをビルドする場合
```powershell
pnpm run build
```
実行後、`dist` フォルダーを Edge の「展開して読み込み」から選択してください。
